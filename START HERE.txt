Tongkat Gaib Excel
========================

No Python install needed - just double-click TongkatGaibExcel.exe

Read SYSTEM DETAILS.txt for the full product explanation (what you bought,
why the reports are built this way, and the proprietary license). This file
is the operator guide.

How to run
----------
1. Double-click TongkatGaibExcel.exe
2. Select a workflow from the dropdown (listed in daily reporting order)
3. Select your source file (pipe-delimited .txt / .csv / .bin, or Excel for Giro)
4. If prompted: select your reference mapping file (.xlsx)
5. If prompted (Qlola / Giro): select the extra workbook
6. Choose where to save the output (.xlsx)
7. Leave the FILTERS boxes empty for the normal report. Only type in them to
   narrow this one run - read "FILTERS - HOW TO USE THEM" below first
8. Click "Run Pipeline"

FILTERS - HOW TO USE THEM (SEGMENT, SOURCE, KW)
===============================================
One box per dimension, shown on every report.

THE ONE RULE
------------
  Empty box  = automatic. The report applies its own normal rule.
  Typed text = keep ONLY what you typed, and the report's normal rule is
               switched OFF for that run.

Read that second line carefully. Typing something REPLACES the normal rule,
it does not add to it. That is the one thing that catches people out - see
"The KORPORASI trap" below.

Each box shows what it does when left empty, e.g. "auto: drops KORPORASI",
so you never have to type the normal rule yourself, and you never have to
clear a box to get it.

WHAT EACH REPORT DOES WHEN THE BOX IS EMPTY
-------------------------------------------
  Report Data Statis    SEGMENT: drops KORPORASI
                        KW:      keeps KANWIL MALANG
  Report Vol Briva      SEGMENT: keeps NONWHOLESALE
  Active User Qlola     SOURCE:  drops CMS
  Every other report    no automatic filtering

THE KORPORASI TRAP
------------------
Typing KORPORASI in the SEGMENT box does NOT mean "add corporate back in".
It means "show me KORPORASI and nothing else".

  SEGMENT empty        ->  everyone EXCEPT corporate   (the normal report)
  SEGMENT "KORPORASI"  ->  corporate ONLY

Both are valid reports, but they are very different numbers. If you want
the full population WITH corporate included, you have to list every segment
you want to see, for example:

  KORPORASI, RITEL, KONSUMER, MIKRO

There is no "keep everything" shortcut: an empty box gives you the report's
normal rule, not everything. The same logic applies to the SOURCE and KW
boxes.

RECIPES
-------
  Normal monthly report      leave all three boxes empty
  Corporate-only cut         SEGMENT: KORPORASI
  Two segments together      SEGMENT: RITEL, KORPORASI
  A different region         KW: KANWIL SURABAYA
  Only one channel           SOURCE: the channel name

ALWAYS CHECK WHAT ACTUALLY RAN
------------------------------
The Summary sheet has a "Filter Applied:" line near the top, and it states
exactly what that run used. For Report Data Statis:

  KORPORASI (excluded); KANWIL MALANG (KW only)   <- the normal report
  KORPORASI (only); KANWIL MALANG (KW only)       <- a corporate-only cut

If that line does not say what you expected, the numbers will not either.
Check it before sending a report on.

SMALL PRINT
-----------
- Comma-separated for several values.
- Matching ignores upper/lower case and extra spaces.
- If your file has no such column the filter simply does nothing - it can
  never fail the run.
- Switching workflow clears all three boxes.

Workflows (dropdown order)
--------------------------
1. Report Summary Akumulasi (needs reference mapping)
2. Time Series Active User Qlola (needs reference + master data)
3. Report Data Statis (needs reference mapping; raw may be a .bin extract)
4. Rincian Vol TF
5. Rincian Portal BG
6. Report Vol Briva (needs reference mapping)
7. Report Giro (needs monthly giro workbook + giro master; no reference mapping)

Qlola (Workflow 2) — three input files
--------------------------------------
1. Raw pipe-delimited .csv (SOURCE, ID, FREKUENSI, KODE_UKER, ...)
2. UKER reference workbook (KODE_UKER -> MAIN_CODE for detail only)
3. Master-data workbook (ID -> MAIN_CODE for the Summary pivot)

For ``MASTER DATA STATIS MALANG`` workbooks, the Qlola user ID lives in the
``ID_PRODUCT`` column (not ``CIF``). The Summary counts users by the master
``MAIN CODE`` after VLOOKUP on ID — same as manual Excel step 4.

Report Data Statis (Workflow 3)
-------------------------------
Raw is pipe-delimited (often a .bin extract). Needs a UKER/unit mapping
workbook. Your file needs a KW column - that is where the region lives.
Reports Count of ID_PRODUCT per branch.

With all boxes empty it keeps KW = KANWIL MALANG and drops SEGMEN KORPORASI.
To report a different region for one run, type it in the KW box. Before you
touch the SEGMENT box, read "The KORPORASI trap" above: typing KORPORASI
gives you a corporate-ONLY report, not the normal report with corporate
added back in.

Report Giro (Workflow 7) — two Excel workbooks
----------------------------------------------
1. Monthly giro source workbook (NO REK + SALDO IDR)
2. Giro master workbook. The original list is enough, for example
   DAFTAR REKENING GIRO TSPM.xls with JENIS, NO REK, PRODUK, OPEN DATE,
   SALDO. If SALDO UPDATE is missing, the program adds it. If the file
   already has SALDO UPDATE or a month column such as SALDO JUNI, that
   existing column is filled instead.

The master you pick is never overwritten. The updated copy is saved as
.xlsx to the output path you choose. Deposito rows are skipped. Accounts
missing from the monthly file are left blank. Historical SALDO is never
changed. Balances are written as plain whole numbers (format 0) -
concatenated digits, no commas and no decimal point.

The FILTERS boxes work here too: they filter the monthly source, so a
filtered-out account keeps whatever its master cell already had. If your monthly
file only has NO REK and SALDO IDR, they simply do nothing.

Reference file column names
---------------------------
The program accepts common alternate headers (not only KODE_UKER):

  Branch lookup:  KODE_UKER, KODE UNIT, KANCA, KODE SUB KANCA, KODE KANCA, UKER, KODE UKER
  Branch code:    MAIN_CODE, MAIN CODE, KODE, KODE KANCA, KODE UNIT, UNIQUE CODE, KODE INDUK
  Branch name:    MAIN_BRANCH, MAIN BRANCH, BRANCH, DESC KANCA, DESC UNIT, SUB KANCA, NAMA UKER, DESCRIPTION

Multi-sheet Excel files are supported - it scans sheets until it finds a match.

Output
------
Creates an Excel report with a Summary sheet (and detail/audit data as applicable).
Report Giro writes an updated copy of the master workbook instead of a pivot.

Troubleshooting
---------------
- Close the output Excel file before running again (can't overwrite an open file)
- If you see "Pipeline failed", read the error - it lists which columns were found
- Codes missing from the reference show as UNMAPPED (report still generates)
- Totals look too low or too high? Check the Summary's "Filter Applied:" line
  before anything else - a typed filter box keeps ONLY what you typed. See
  "FILTERS - HOW TO USE THEM" above.

Sample raw data format (your .txt / .csv file should look like this):

  KODE_UKER|SEGMEN|VOLUME_IN_IDR
  0001|Wholesale|1250000000000
